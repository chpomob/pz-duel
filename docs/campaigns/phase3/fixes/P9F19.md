# P9F19 — Choisir le type de zombie envoyé, avec « aléatoire » par défaut

commit: feat(phase3): P9F19 — type de zombie envoyé réglable, aléatoire par défaut

## Contexte

Les zombies envoyés arrivent habillés au hasard : `spawnAt` appelle
`addZombiesInOutfit(x, y, 0, count, nil, nil)`, et le cinquième argument est justement le **nom de
l'uniforme** (`String`), le sixième une variante de peau. Le propriétaire veut pouvoir choisir ce
type dans les réglages, avec une jolie liste et **« aléatoire » par défaut** — ce qui garde le
comportement actuel tant qu'on n'y touche pas, et permettra plus tard de reconnaître d'un coup d'œil
les zombies de l'adversaire.

Noms d'uniformes présents dans le jeu (relevés dans le jar) : `Fireman`, `Police`, `Doctor`, `Nurse`,
`Farmer`, `Hunter`, `Ranger`, `Trapper`, `Chef`, `Mechanic`.

## Ce que l'étape doit faire

### 1. Le catalogue apprend les choix textuels

Le catalogue ne connaît aujourd'hui que des choix **numériques** (`Zombies` : 1 = Hardcore … 6 =
Aucun) : la page convertit la valeur avec `Number(...)`, et le service valide à coups de comparaisons
numériques. Il faut un type `choice` dont les valeurs sont des **chaînes** :

- `service/settings.py` : un champ `type: "choice"` dont `choices` porte `{value: "<chaîne>", label:
  "<français>"}`, avec `defaut` une des valeurs ;
- validation : la valeur reçue doit être **exactement** une des valeurs proposées, sinon refus nommant
  la clé **et la liste acceptée** ; aucune valeur approchante, aucune casse corrigée en silence ;
- `ui/app.js` : pour `type === 'choice'`, ne plus passer par `Number()` — la valeur part telle quelle.

### 2. Le champ, dans les règles

Nouveau champ `zombie_outfit`, groupe **Règles**, type `choice`, juste après `zombies_par_kill` :

- valeur `random`, libellé « Aléatoire (comme aujourd'hui) », **défaut** ;
- puis un libellé par uniforme : Pompier (`Fireman`), Policier (`Police`), Médecin (`Doctor`),
  Infirmière (`Nurse`), Fermier (`Farmer`), Chasseur (`Hunter`), Ranger (`Ranger`), Trappeur
  (`Trapper`), Cuisinier (`Chef`), Mécanicien (`Mechanic`) ;
- aide : « L'uniforme des zombies envoyés. Aléatoire garde le tirage du jeu. »

### 3. Jusqu'au zombie

- l'arbitre inscrit le choix dans le preset effectif et le passe dans la commande de pop (`outfit`) ;
- le mod lit `outfit` et appelle `addZombiesInOutfit(x, y, 0, count, outfit, nil)` ; `random` (ou une
  clé absente) donne `nil`, c'est-à-dire le tirage du jeu, donc **le comportement actuel à l'octet** ;
- les deux effets de pop (`spawn_pop`, `spawn_sprinter`) portent le même uniforme : le sprinter est
  rapide, pas habillé autrement ;
- la commande est journalisée avec `outfit` ; un journal qui ne l'a pas se rejoue en aléatoire.

### 4. Le risque, écrit plutôt que caché

Un nom d'uniforme absent d'une version du jeu ne produit **aucune erreur** : les zombies sortent
habillés au hasard, et l'on croirait le réglage inopérant. Le journal porte le nom demandé, ce qui
permet de trancher ; `limites-connues.md` le dit, avec la phrase « vérifié à l'écran sur 42.22.2 ».

  `README.md`, `README.fr.md`, `docs/campaigns/phase3/limites-connues.md`.
- Aucun test existant ne doit être affaibli : les choix numériques continuent d'être validés comme
  avant, et `random` par défaut ne change aucun octet du zombie produit.
- Un test par comportement, qui **échoue si la correction est retirée**, mutation citée :
  - le catalogue expose `zombie_outfit` avec `random` par défaut et dix valeurs ;
  - une valeur inconnue est refusée, et le message nomme la clé et la liste ;
  - une valeur choisie arrive dans la commande de pop et dans le journal ;
  - `random` produit `outfit = nil` côté mod (comportement d'aujourd'hui) ;
  - la page n'applique pas `Number()` sur un champ `choice` (test statique du source, comme les autres).
- Un seul commit, sujet exactement :
  `feat(phase3): P9F19 — type de zombie envoyé réglable, aléatoire par défaut`.

## Definition of done

- Un choix dans les Règles, avec « Aléatoire » par défaut, et dix uniformes proposés.
- Le choix traverse arbitre → commande → mod → `addZombiesInOutfit`.
- Une valeur inconnue est refusée avant le lancement, sans énumération vague.
- `.venv/bin/python -m pytest -q` vert, plus de tests qu'avant, 16 skips inchangés.
- Un seul commit, sujet ci-dessus.
- Réponse finale en français : ce que voit l'utilisateur, ce que reçoit le jeu, et ce qui reste à
  vérifier à l'écran (chaque uniforme existe et se distingue vraiment).
