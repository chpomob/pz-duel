# P9F7 — Les ports externes que les box françaises acceptent

commit: feat(phase3): P9F7 — ports externes dans la plage des box, invitation qui les porte

## Contexte, mesuré et documenté

Premier duel réel (2026-11-10) : l'UPnP a posé puis retiré les trois mappings sur une Freebox, bail
honoré (7 190 s), invitation servie depuis le port de partage — mais **seulement après avoir déplacé
les ports du jeu** de 17271/17272/17280 vers 49271/49272/49280 à la main dans `runtime.json`. En
l'état livré, le bouton ne peut donc jamais réussir sur cette box, et le testeur non plus.

Mesures sur l'IGD `192.168.1.254` (`WANIPConnection:1`) :

- `AddPortMapping` rend **718 (ConflictInMappingEntry)** pour tout port externe **< 49152**
  (1024, 8080, 17271, 40000, 49151), alors que `GetSpecificPortMappingEntry` rend **714 (absent)** sur
  ces mêmes ports : la box dit « conflit » sans qu'il y ait d'entrée.
- `49152`, `50000`, `51414`, `65535` sont **acceptés**.
- `49271 -> 17271/UDP` (externe ≠ interne) fonctionne : entrée créée, relue avec `NewLeaseDuration`
  7199, puis supprimée et vérifiée absente.
- Mapper vers un autre poste du LAN rend **606 (non autorisé)**.

Règles relevées sur le net pour les quatre grands FAI :
- **Freebox** : redirections et UPnP limités à 49152-65535 (49151 refusé, 49152 accepté, mesuré).
- **SFR / Neufbox** : même recommandation explicite (« se servir des ports entre 49152 et 65535 ») ; des
  utilisateurs documentent le 718 sur un port libre.
- **Bbox** : redirections conseillées de 49152 à 64034 ; des sujets parlent d'une limitation récente des
  ports disponibles.
- **Livebox** : UPnP actif, mais en IPv4 partagée les ports sont découpés par tranches ; hors tranche,
  rien n'arrive (CGNAT).

## Ce que l'étape doit faire

### 1. Des ports externes configurables, par défaut dans la plage acceptée

`service/runtime.json` reçoit une section dédiée, par exemple

    "upnp": { ..., "external_ports": { "udp_game": 49271, "udp_aux": 49272, "tcp_share": 49280 } }

Les ports **internes** ne changent pas (`ports.B.game` 17271, `ports.B.udp` 17272, `share_port` 17280) :
c'est le serveur qui écoute, il n'a aucune raison de bouger. Ce sont les externes qui voyagent.

Validation comme les autres réglages : entier 1024-65535, trois valeurs distinctes, et un contrôle qui
**refuse** une valeur sous 49152 en avertissant que la plupart des box françaises la rejetteront (le
refus dur serait faux sur une box permissive : c'est un avertissement, pas une erreur).

### 2. Un repli sur `718`, pas une devinette

Quand `AddPortMapping` rend 718 sur un externe configuré, l'ouverture **réessaie une fois** avec les
trois externes de la plage de repli (`49152-50175`, configurable), de façon déterministe : les trois
suivants libres à partir du premier. Si le repli réussit, le résultat porte les externes **réellement
ouverts**. Si les deux échouent, le statut reste `refused` avec le code de la box et la consigne
manuelle.

Aucun essai en boucle : deux tentatives au maximum, dans un budget borné par les délais existants.

### 3. L'invitation porte toujours l'externe

`invite.port` (et donc le `.bat`) porte le port **externe réellement ouvert**, jamais l'interne. Quand
aucun mapping n'a été posé (box sans UPnP, CGNAT, refus), l'invitation porte l'externe configuré et le
lobby affiche la correspondance à recopier dans la box : `49271 -> 17271/UDP`, `49272 -> 17272/UDP`,
`49280 -> 17280/TCP`.

Le `.bat` construit déjà `+connect hôte:port` (`service/guest_launcher.py:234`) : rien à changer côté
invité, et le test doit le prouver en lisant le port dans le fichier produit.

### 4. Le CGNAT est dit avant l'essai

Si l'adresse lue n'est pas publique (privée, `10.0.0.0/8`, `100.64.0.0/10`, `192.168.0.0/16`), le
lobby l'annonce **avant** de proposer d'ouvrir des ports, avec la conséquence : aucune redirection ne
rendra le duel joignable depuis Internet. Le comportement existant est conservé et complété.

### 5. Ce que le README doit dire

Une section courte : les box françaises réservent les ports sous 49152 ; PZ Duel ouvre donc des ports
externes dans la plage haute et laisse le jeu écouter sur ses ports habituels ; si ta box refuse
encore, la correspondance externe→interne est affichée pour la saisie manuelle.
