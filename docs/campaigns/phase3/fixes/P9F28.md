# P9F28 — Le test d'annulation ne dépend plus du délai de disponibilité

commit: fix(phase3): P9F28 — test d'annulation de la passe de création déterministe

## Contexte

CI rouge sur `1a99a49` (P9F27), un seul job : `pytest-windows (3.12)`.

    FAILED tests/test_snapshots.py::test_cancelled_creation_pass_captures_nothing
    AssertionError: Regex pattern did not match.
      Expected regex: 'passe de création en échec : interrompue'
      Actual message: 'passe de création en échec : serveur A : pas de disponibilité après 10 s ;
                       monde partiel invalidé'

Le test programme `pair.stop` par un `threading.Timer(CANCEL_DELAY_S)` et attend que la passe de
création s'arrête sur l'annulation. Sur un runner Windows plus lent, le **délai de disponibilité de
10 s** expire avant que l'annulation prenne effet : la passe s'arrête bien, mais pour une autre raison.

Le comportement produit est correct dans les deux cas — la passe s'interrompt, rien n'est capturé, le
monde partiel est invalidé. C'est le test qui exige une raison précise, alors que ce qu'il veut
vérifier est l'invariant.

Troisième récidive de la même famille après P9F24 et P9F27 : un test qui suppose le moment d'un
événement au lieu de vérifier ce qui doit rester vrai.

## Ce que l'étape doit faire

### 1. Vérifier l'invariant, pas la raison

L'assertion porte sur ce qui compte, et qui est vrai dans les deux courses :

- une `SnapshotError` est levée, et son message **commence** par « passe de création en échec » ;
- aucun monde n'est capturé (`has` faux des deux côtés, pas de ``capture`` dans les événements) ;
- aucune passe de création n'est en attente, et aucun serveur ne tourne.

La raison exacte n'est pas affirmée. Si l'étape veut garder une trace des deux courses, elle peut
constater que le message nomme soit « interrompue », soit le serveur en attente — en le documentant
dans le test, sans en faire une condition de réussite.

### 2. Le même défaut, s'il existe ailleurs

Recenser dans `tests/test_snapshots.py` les assertions qui contiennent une raison complète
(`match="… : interrompue"`, `match="… : serveur …"`) et les traiter pareil : préfixe et invariant
d'abord, raison seulement quand elle est déterministe.

### 3. Une preuve qui tient sous charge

Le test doit passer **25 fois de suite**, et passer aussi avec un délai de disponibilité artificiellement
raccourci (par exemple 0,2 s) : c'est la forme qui reproduit un runner lent. La spec demande de le
vérifier et de citer la sortie.
