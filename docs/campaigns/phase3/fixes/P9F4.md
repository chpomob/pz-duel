# P9F4 — Arrêt automatique sur inactivité, et doc rectifiée

commit: feat(phase3): P9F4 — arrêt sur inactivité, jamais pendant un duel

## Contexte

Naylo, premier testeur Windows, rapporte : « il te faut un truc qui désactive le .exe quand le
process s'arrête, parce qu'il tourne en permanence sinon ». Il a raison, et c'est structurel : PZ Duel
est un service HTTP local dont l'UI est un onglet de navigateur. Les seules sorties existantes sont
`/api/quit` (`service/api.py:374`) et les signaux (`service/main.py:229-241`). Fermer l'onglet ne fait
rien : `pz-duel.exe` reste, garde son verrou d'instance, et si un duel tournait les serveurs Java
restent avec lui — le Job Windows `KILL_ON_JOB_CLOSE` (`service/platforms.py:462`) ne les tue que
lorsque le service s'arrête vraiment.

Décision du propriétaire du produit : **1a + 2**, à savoir
- arrêt automatique quand plus personne ne regarde le service : aucun appel `/api/state` depuis
  `idle_quit_s` secondes **et** aucun match en cours ;
- `idle_quit_s` dans `runtime.json`, **120 s** par défaut, et l'UI l'affiche.

## Ce que l'étape doit faire

1. **Un battement de vie côté service.** La route `/api/state` (`service/api.py:271`) note l'instant du
   dernier appel. Aucune autre route ne compte : un `GET /` ramène la page, ce n'est pas quelqu'un qui
   regarde. L'horloge reste injectable, comme ailleurs dans le service : le test ne dort pas.
2. **Un chien de garde qui s'arrête proprement.** Quand `maintenant - dernier_battement >= idle_quit_s`
   **et** que l'état n'est pas un match en cours (voir 3), le service prend le même chemin que `Quit` :
   `engine.shutdown()` puis arrêt du serveur HTTP — jamais un `os._exit`, jamais sans relâcher les ports
   UPnP ni les serveurs (le Job Windows s'en charge si le processus meurt, mais l'arrêt propre doit
   retirer les mappings).
3. **Ne jamais couper un duel.** Un match en cours interdit l'arrêt, même sans aucun navigateur : c'est
   le scénario où l'hôte regarde le jeu, pas l'onglet. La condition exacte sur les phases est à écrire
   dans le code et à citer dans la réponse ; les phases « lobby » et « erreur » ne protègent pas.
4. **L'UI le dit.** Quand le décompte approche (au moins dans les dernières 30 s), l'UI affiche qu'elle
   va se fermer faute de spectateur, et qu'un clic n'importe où dans la page suffit à rester. Si des
   ports sont ouverts, le message le dit : ils seront refermés proprement.
5. **`idle_quit_s` est configurable** dans `service/runtime.json` (`0` = jamais d'arrêt automatique),
   validé comme les autres durées (positif fini, ou exactement 0), et refusé s'il est négatif.
6. **Documentation.** Dans les deux README, à l'endroit où `Quit` est décrit : PZ Duel se ferme seul
   après `idle_quit_s` sans personne qui regarde, jamais pendant un duel, et fermer l'onglet suffit à
   déclencher ce compte à rebours.
7. **Les deux rectifications de doc laissées en attente** :
   - expliquer une fois, côté installation, que le binaire `--onefile` débaralle le mod dans
     `%LOCALAPPDATA%\Temp\_MEI…\` à chaque lancement et que le mod **installé** est
     `%USERPROFILE%\Zomboid\mods\duelcore` — c'est ce chemin-là que le jeu charge, et `%LOCALAPPDATA%\PZDuel`
     ne contient que le journal, les matchs et le verrou d'instance ;
   - la phrase « cliquer à nouveau remplace les mêmes trois redirections, il n'en ajoute pas de
     nouvelles » est exacte pour une box, imprécise quand deux box ont été jointes dans la même
     session : la reformuler.
