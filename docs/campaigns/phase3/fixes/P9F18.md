# P9F18 — Le code du lanceur devient une option, éteinte par défaut

commit: feat(phase3): P9F18 — code du lanceur en option, éteint par défaut

## Contexte

Retour du propriétaire après usage : « le coup du code launcher à passer, c'est pénible, et je pense
que c'est overkill pour protéger le mot de passe d'un serveur PZ pour un duel en one shot. Ne le garder
que si on met une option spécifique au lancement, pour les paranos. »

Il a raison sur le fond : le code protège contre un fichier **remplacé**, pas contre un lien intercepté.
Pour un duel entre deux personnes qui se parlent, le coût (dicter seize caractères hexadécimaux, les
faire recopier, un lanceur qui refuse de démarrer si l'on se trompe) dépasse largement le risque
couru sur un mot de passe de serveur qui ne vit qu'une partie.

## Ce que l'étape doit faire

### 1. Une option au lancement, éteinte par défaut

Le corps de `POST /api/action {"action":"start", …}` accepte `launcher_check: true|false`, **faux par
défaut**. `/api/state` l'expose (`launcher_check`) pour que l'interface montre l'état retenu.

L'interface : une case à cocher, à côté du choix « qui joue » — « Vérifier le code du lanceur
(paranoïaque) », décochée. Elle ne doit pas dominer l'écran : une ligne, avec une phrase courte
expliquant ce qu'elle protège.

### 2. Code éteint : un lanceur direct

Quand l'option est fausse :

- le `.bat` **ne demande rien** : il installe le mod puis lance le jeu, comme n'importe quel
  exécutable. Aucun `pause`, aucune comparaison, aucun appel à `certutil` ;
- l'invitation **ne porte pas** `launcher_code` ni `launcher_code_text` : le lobby n'affiche plus de
  gros code, seulement le lien, le bouton « Copier », le `.bat` à enregistrer, et le mot de passe
  serveur pour un ajout manuel ;
- une phrase unique remplace l'avertissement de seize lignes actuel : « Ce fichier contient le mot de
  passe du serveur : envoie-le par un canal privé, et supprime-le après la partie. »

Le marqueur `::PZDUEL-JOIN <ip> <port> <mdp>` reste, avec le mot de passe : c'est ainsi que le lanceur
retrouve ses paramètres, et c'est aussi ce qui permet à l'option de n'être qu'un contrôle en plus.

### 3. Code allumé : le comportement d'aujourd'hui, intact

`launcher_check: true` reproduit exactement le lanceur actuel — code affiché dans le lobby, saisie
obligatoire, `certutil -hashfile` comparé aux seize premiers caractères, refus net si le fichier ne
correspond pas, restauration du mod précédent. Aucune assertion existante ne doit changer de sens :
c'est la garantie que l'option protège encore vraiment.

### 4. Ce que la documentation doit dire

`README.md`, `README.fr.md` et `limites-connues.md` : le code est **éteint par défaut**, ce qu'il
protège, ce qu'il ne protège pas (un lien intercepté reste capable de lancer le jeu et de se connecter)
et comment l'allumer. Pas de formulation rassurante : un fichier remplacé, code éteint, s'exécute.

## Règles

- Fichiers autorisés : `service/guest_launcher.py`, `service/engine.py`, `service/runtime.json`,
  `ui/app.js`, `ui/index.html`, `tests/test_guest_launcher.py`, `tests/test_match.py`,
  `tests/test_setup_flow.py`, `tests/test_share.py`, `README.md`, `README.fr.md`,
  `docs/campaigns/phase3/limites-connues.md`.
- Aucun test existant sur le code affiché ne doit être supprimé : il est **conditionné** à l'option,
  pas effacé.
- Un test par comportement, qui **échoue si la correction est retirée**, mutation citée :
  - par défaut, le `.bat` ne contient ni saisie ni `certutil`, et se termine par le lancement ;
  - par défaut, l'invitation n'a ni `launcher_code` ni `launcher_code_text` ;
  - l'option à `true` redonne exactement l'ancien lanceur (saisie, `certutil`, refus sur mauvais code) ;
  - le marqueur `::PZDUEL-JOIN` porte bien les trois valeurs dans les deux modes ;
  - l'écran de lancement envoie `launcher_check` dans le corps du `start`.
- Un seul commit, sujet exactement :
  `feat(phase3): P9F18 — code du lanceur en option, éteint par défaut`.

## Definition of done

- Défaut : un `.bat` qui ne demande rien, et un lobby sans code.
- Option cochée : le comportement actuel, inchangé, prouvé par les tests existants reconditionnés.
- La documentation dit ce qui est perdu quand le code est éteint.
- `.venv/bin/python -m pytest -q` vert, plus de tests qu'avant (2 973), 16 skips inchangés.
- Un seul commit, sujet ci-dessus.
- Réponse finale en français : ce que voit l'invité dans les deux modes, ce que l'option protège
  encore, et ce que la documentation reconnaît ne plus protéger.
