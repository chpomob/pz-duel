# P9F13 — Un lobby qui dit quoi faire, avec le bon code en gros

commit: feat(phase3): P9F13 — lobby lisible : le code du lanceur en clair, le QR replié, une seule action

## Contexte

Retour du propriétaire après une vraie session : « la page web pour se connecter est peu pratique, un
gros QR code et un code en gros qui servent pas, le vrai code et le bouton jouer sont peu visibles ».

C'est exact, et c'est mesurable dans le code : le bloc d'invitation (`ui/app.js`, section
`renderInvite`) affiche d'abord le QR (`<div class="qr">`), puis le lien, puis `inv.code` en gros
(`<div class="code">`), et seulement ensuite le code du lanceur dans un `<div class="secret">` avec
un libellé d'aide. Autrement dit : les deux choses décoratives sont en haut, les deux choses utiles
sont noyées. Le QR ne sert qu'à un téléphone, ce qui n'est pas le cas d'usage d'un duel sur PC.

## Ce que l'étape doit faire

### 1. Trois zones, dans l'ordre où l'on s'en sert

La carte d'invitation devient, de haut en bas :

1. **Ce que tu fais maintenant** — une seule action primaire, pleine largeur, avec son état
   (« ouvrir le jeu », « attendre l'adversaire », « lancer le duel » selon la phase). C'est le premier
   élément cliquable de la carte, et le seul bouton accentué.
2. **Ce que tu dictes à l'oral** — le **code du lanceur** en gros, en police monospace, sélectionnable
   et copiable d'un clic, avec une phrase courte qui dit à quoi il sert et ce qu'il n'est pas.
3. **Ce que tu envoies** — le lien d'invitation, en secondaire, avec un bouton « Copier » ; et le QR
   **replié** derrière un `<details>` « Afficher le QR (téléphone) », fermé par défaut.

### 2. Ce qui disparaît

- `inv.code` (le jeton d'invitation affiché en gros) **n'est plus rendu** : il ne sert à rien au
  joueur, il encombre, et il ressemble à s'y méprendre au code du lanceur — c'est précisément ce qui a
  fait saisir le mauvais code au testeur (P9F5). Le champ peut rester dans l'API pour compatibilité,
  mais l'interface ne l'affiche plus.
- La phrase « Ton adversaire n'aura qu'à scanner le QR » (`ui/app.js:352`) est remplacée : elle décrit
  le mauvais geste.

### 3. Ce qui ne change pas

- **Deux secrets restent séparés** : le code du lanceur (à dicter) et le mot de passe serveur (pour un
  ajout manuel). Le texte d'explication existant reste, déplacé sous le bloc concerné.
- Aucun changement de protocole, aucun nouvel appel d'API, aucun réglage de preset.
- Les mentions de sécurité existantes (ne pas envoyer le `.bat`, comparer le code) restent visibles.
