# P9F16 — La compilation du double Windows ne doit plus faire rougir la CI

commit: fix(phase3): P9F16 — compilation du double Windows bornée, réessayée et lisible

## Contexte

CI rouge sur `392f4df`, commit qui ne touchait qu'un fichier Markdown : côté Windows,
**2861 passed, 34 skipped, 36 errors**. Les 36 erreurs viennent toutes du même fixture :

    ERROR at setup of test_windows_launcher_installs_the_mod_and_connects
    subprocess.TimeoutExpired: Command '['...csc.exe', '/nologo', '/out:...client.exe',
    '...client.cs']' timed out after 120 seconds

`tests/doubles/fake_server.py:71` : `COMPILE_TIMEOUT_S = 120`, et `compile_windows_client`
l'utilise tel quel. Sur un runner chargé, la compilation à froid d'un petit programme C# par
`csc.exe` du .NET Framework dépasse deux minutes, le fixture de session échoue, et **tous** les tests
qui en dépendent tombent en erreur. Rien à voir avec le code du produit : c'est l'outillage qui décide
de la couleur du dépôt.

Le fixture est déjà `scope="session"`, donc une compilation par job ; le problème est uniquement la
borne de temps et l'absence de reprise.

## Ce que l'étape doit faire

### 1. Une borne réaliste, réglable, et mesurée

- `COMPILE_TIMEOUT_S` passe à **900 s**, et se lit d'abord dans l'environnement
  (`PZDUEL_COMPILE_TIMEOUT_S`) : un runner lent se règle sans toucher au code.
- La durée réelle de la compilation est **mesurée et imprimée** (`compile_windows_client: compiled in
  X.Xs`), pour qu'on voie dans les journaux de CI si l'on s'approche de la borne.

### 2. Une reprise, puis une erreur qui dit quoi faire

- Sur `subprocess.TimeoutExpired`, une **seconde tentative** est faite après avoir supprimé un `client.exe`
  partiel. Une seule : au-delà, c'est le runner, pas un aléa.
- Si les deux échouent, l'erreur levée n'est plus un `TimeoutExpired` brut mais un `RuntimeError` qui
  nomme le compilateur, la borne utilisée et la variable d'environnement à monter. Un test qui échoue
  doit dire quoi faire.
- Ni `skip` ni `xfail` : ces tests doivent continuer d'échouer franchement quand Windows est cassé.

### 3. Une seule compilation par session, partout où c'est possible

`tests/test_platform_windows.py:2037` compile dans un test ; les deux autres points d'appel
(`test_guest_launcher.py:619`, `test_modes.py:662`) sont déjà en session. Passer ce troisième à un
fixture `scope="session"` s'il ne teste pas lui-même la compilation.

## Règles

- Fichiers autorisés : `tests/doubles/fake_server.py`, `tests/test_guest_launcher.py`,
  `tests/test_platform_windows.py`, `tests/test_modes.py`, `.github/workflows/tests.yml`,
  `docs/campaigns/phase3/limites-connues.md`.
- Aucun test ne doit devenir plus permissif : la borne monte, la vérification reste identique.
- Un test par comportement, qui **échoue si la correction est retirée**, mutation citée :
  - la borne par défaut est 900 s et se lit dans `PZDUEL_COMPILE_TIMEOUT_S` ;
  - un premier `TimeoutExpired` suivi d'un succès rend un client valide, et le compilateur a été
    appelé **deux fois** ;
  - deux échecs lèvent un `RuntimeError` nommant la variable d'environnement ;
  - la durée mesurée est transmise (au moins journalisée) ;
  - un test de plateforme qui compilait par test utilise le fixture de session.
- Ces tests ne lancent pas `csc.exe` : ils remplacent le compilateur par un double (fichier ou appel
  enregistré), pour tourner sous Linux comme sous Windows.
- Un seul commit, sujet exactement :
  `fix(phase3): P9F16 — compilation du double Windows bornée, réessayée et lisible`.

## Definition of done

- `COMPILE_TIMEOUT_S` = 900 s réglable par `PZDUEL_COMPILE_TIMEOUT_S`, durée imprimée.
- Un timeout est réessayé une fois ; deux échecs donnent un message actionnable.
- Une compilation par session aux trois points d'appel.
- `.venv/bin/python -m pytest -q` vert sous Linux, plus de tests qu'avant (2 895), 16 skips inchangés.
- Un seul commit, sujet ci-dessus.
- Réponse finale en français : la nouvelle borne, ce que fait la reprise, ce que dit l'erreur, et le
  fait que la preuve finale est **la CI Windows verte** sur ce commit — à vérifier après le push.
