# P19F4 — Le test de politique d'exécution casse la CI Windows au lieu de prouver quoi que ce soit

commit: fix(phase2): P19F4 — Prouver l'absence de Set-ExecutionPolicy persistant sans dépendre du runner

## Contexte

CI réelle du commit `2611175` (run **42357926574**) :

```
pytest (3.12) (3.13) (3.14)          ✓   2175 passed, 5 skipped
build-windows                        ✓
pytest-windows (3.12) (3.13) (3.14)  ✗   1 failed, 2200 passed, 32 skipped
```

Le point important d'abord : les neuf tests qui exécutent le vrai `-Command` du `.bat` via `pwsh`
**tournent bien sur `ubuntu-latest`** (2 175 passés contre 2 166 en local, où `pwsh` manque). Le
contrôle embarqué est donc réellement exercé.

L'unique échec Windows est `tests/test_guest_launcher.py:695-701` :

```
_______ test_windows_execution_policy_is_unchanged_after_a_run _______
E  subprocess.CalledProcessError: Command '['powershell.exe', '-NoProfile', '-Command',
   'Get-ExecutionPolicy -List | Out-String']' returned non-zero
tests\test_guest_launcher.py:695: CalledProcessError
```

Le test sonde la politique d'exécution du **runner** avec `check=True`. Que la sonde elle-même échoue
ne dit rien de notre code : le test casse la CI sans avoir rien prouvé.

## Correction attendue

- **La preuve principale devient statique et déterministe** : le `.bat` généré et son `-Command` ne
  contiennent aucun `Set-ExecutionPolicy` persistant ; la seule politique mentionnée est portée par
  l'invocation du processus (`-ExecutionPolicy Bypass` sur la ligne `powershell`). Cette assertion
  doit rester stricte, et échouer si on introduit un `Set-ExecutionPolicy` dans le lanceur — vérifie-le
  par mutation.
- **La sonde dynamique devient tolérante à l'environnement** : si `powershell.exe` refuse de répondre
  (code de sortie non nul), le test **saute cette moitié** avec un motif qui cite le code de sortie et
  la première ligne de `stderr` — pas un `skip` muet, pas un `check=True` qui explose.
- Si la sonde répond, le test garde son exigence : la politique avant et après doit être identique.
- Le test ne doit plus jamais faire échouer la CI à cause d'un environnement qui refuse de répondre, et
  ne doit jamais passer silencieusement si le lanceur persiste réellement une politique.

## Preuve exigée

- Sous Linux, la suite reste verte. Compte exact à retrouver et à annoncer sans le maquiller : en
  local `pwsh` est absent, donc neuf tests sont sautés (2 166 passés, 14 skips).
- Mutations à vérifier et à raconter : (a) ajouter un `Set-ExecutionPolicy` dans le lanceur doit faire
  échouer l'assertion statique ; (b) simuler une sonde qui rend un code non nul doit produire un skip
  motivé, pas un échec.
- CI Windows : les trois `pytest-windows` doivent repasser au vert. C'est l'opérateur qui relancera.

## Règles

- Fichiers autorisés : `tests/test_guest_launcher.py` uniquement. Si la correction exige de toucher
  `service/guest_launcher.py`, arrête-toi et explique pourquoi.
- Aucune assertion de sécurité retirée : le test doit toujours attraper un `Set-ExecutionPolicy`
  persistant.
- Un seul commit, sujet : `fix(phase2): P19F4 — Prouver l'absence de Set-ExecutionPolicy persistant sans dépendre du runner`.
- Réponse finale en français : ce qui est prouvé statiquement, ce que fait la sonde quand elle échoue,
  et comment tu as vérifié les deux mutations.
