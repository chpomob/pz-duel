# P18F1 — `os.sync()` n'existe pas sous Windows

commit: fix(phase2): P18F1 — Synchronisation disque disponible sous Windows

## Contexte

La CI réelle de la phase 2 (`tests` sur `aff6fb6`, run GitHub Actions 42265105950) est verte sur
Linux (3.12, 3.13, 3.14) et le binaire Windows se construit et passe son test de fumée. Mais les
**trois jobs `pytest-windows` échouent**, tous pour la même cause, 696 fois dans le log :

    E  AssertionError: lancement impossible : AttributeError: module 'os' has no attribute 'sync'
    E  assert 'error' == 'lobby'
    tests\test_contract.py:235

Coupable : `service/snapshots.py:116` et `:209` appellent `os.sync()`, qui n'existe pas sous
Windows. Toute préparation de match réel meurt donc au lancement, et les tests qui bootent un
match (contrat, match, serveurs) tombent en cascade.

Les tests de la phase ne l'ont pas vu parce qu'ils injectent la plateforme : le nom d'API POSIX
restait dans le code, hors du chemin injecté.

## Correction attendue

- Une seule primitive de synchronisation disque, dans `service/platforms.py`, choisie par
  plateforme : `os.sync()` sous POSIX, et sous Windows l'équivalent disponible sans dépendance
  (`os.fsync` sur le descripteur concerné, ou l'absence de synchronisation globale assumée et
  documentée). Aucun `os.sync` ne doit rester dans `service/`.
- `service/snapshots.py` appelle cette primitive, sans changer son comportement observable sous
  Linux (les snapshots restent restaurés avant le lancement, dans le même ordre).
- Un test qui exécute la primitive sous `windows-latest` et sous Linux, et un test qui vérifie
  qu'aucun module de `service/` ne référence `os.sync` en direct.
- `tests/test_ci_workflows.py` liste aujourd'hui `os.sync` parmi les constructions POSIX suivies :
  mets-le à jour pour qu'il décrive l'état corrigé, sans supprimer le contrôle.

## Preuve exigée

- La suite complète passe sous Linux (2 064 tests, 5 skips) — aucune assertion retirée.
- Les trois jobs `pytest-windows` passent sur la CI réelle après merge : c'est la seule preuve qui
  compte pour cette étape, et elle est produite par un push, pas par un test local.

## Règles

- Ne modifie que `service/platforms.py`, `service/snapshots.py`, `tests/test_ci_workflows.py` et le
  fichier de test de la primitive.
- Aucun test existant n'est supprimé, ignoré ou affaibli.
- Un seul commit, sujet : `fix(phase2): P18F1 — Synchronisation disque disponible sous Windows`.
- Réponse finale en français : mécanisme choisi pour Windows, fichiers touchés, tests ajoutés.
