# P18F2 — Les dix échecs Windows de la CI réelle

commit: fix(phase2): P18F2 — Rendre les tests Windows fidèles au vrai comportement

## Contexte

CI réelle du commit `2a9ffd4` (run GitHub Actions **42296912989**) :

```
pytest (3.12) (3.13) (3.14)   ✓   Linux
build-windows                 ✓   le .exe se construit, test de fumée vert
pytest-windows (3.12)         ✗   10 failed, 2094 passed, 29 skipped (19 min 17)
pytest-windows (3.13)         ✗
pytest-windows (3.14)         ✗
```

Les 10 échecs de Windows 3.12 se rangent en quatre classes. C'est la preuve que la phase doit
traiter ; aucune assertion ne doit être supprimée ou affaiblie pour faire passer la CI.

### A. L'arbre de processus n'atteint jamais l'état « prêt » (5 échecs)
`tests/test_platform_windows.py:1594` (`ready_tree`) :
```
wait_until(lambda: server.ready and len(tree_pids(server.log_tail())) ...)
timeout_s = 30
E  AssertionError: condition jamais atteinte
```
Le double de serveur ne devient pas `ready` sous Windows dans les 30 s. Le double doit produire le
même marqueur de sortie que `StartServer64.bat` en vrai (ligne `SERVER STARTED` sur stdout), et la
détection de l'arbre doit voir le processus enfant `java` du `.bat`. Corrige la fidélité du double
et/ou la détection, pas le délai.

### B. Palier d'arrêt attendu : `stdin` contre `sigterm`
```
AssertionError: assert 'sigterm' == 'stdin'
```
Sous Windows il n'y a pas de SIGTERM. Soit le palier `sigterm` est inatteignable et le test doit
attendre le palier réel de la plateforme, soit le vocabulaire doit distinguer les deux. Décide et
écris la règle : le vocabulaire de `stop_stage` reste celui du plan (`rcon`, `stdin`, `sigterm`,
`sigkill`), et un palier qui n'existe pas sur la plateforme est **sauté**, pas renommé.

### C. La boucle de remplacement dépasse son budget de tentatives
`tests/test_platform_windows.py:525` :
```
assert held.attempts <= math.ceil(budget_s * 1000 / SHORT_POLICY["replace_retry_ms"]) + 1
E  assert 12 <= (10 + 1)
```
Le budget est exprimé en millisecondes mais ne borne pas le **nombre** de tentatives : sous Windows
chaque essai coûte moins que le pas de veille, donc la boucle dépasse. Le produit doit borner les
deux : temps **et** tentatives, la seconde borne dérivée du budget et du pas, sans valeur en dur
nouvelle hors `runtime.json`.

### D. Un dossier temporaire reste après le test
```
AssertionError: assert not [WindowsPath('C:/Users/runneradmin/AppData/Local/Temp/pytest-of-...')]
```
Un test laisse un dossier derrière lui sous Windows (verrou de fichier ou nettoyage conditionnel).
Identifie le test et la ressource, et rends le nettoyage inconditionnel.
