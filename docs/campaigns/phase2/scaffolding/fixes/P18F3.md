# P18F3 — Les deux derniers échecs Windows : deux tests qui se trompent de marge

commit: fix(phase2): P18F3 — Deux attentes Windows qui ne laissaient aucune marge

## Contexte

CI réelle du commit `92b7e7f` (run **42309448633**) : Linux vert partout, `build-windows` vert,
et les trois `pytest-windows` tombent avec **2 échecs chacun** (2 failed, 2113 passed, 29 skipped).
Les huit autres ont été fermés par P18F2. Les deux qui restent ne sont pas des défauts produit :

### A. `tests/test_snapshots.py:232` — l'attente dure exactement la fenêtre qu'elle attend
```
AssertionError: attendu en 10 s : return self.until(lambda state: state["phase"] in phases)
  ; observé : {'phase': 'contract', ...}
tests\test_snapshots.py:232
```
`WAIT_S = 10` (ligne 129) et la même valeur est posée en `contract_timeout_s` (ligne 151) : la
fenêtre de contrat dure exactement le délai d'attente, donc la transition ne peut être observée que
par chance. Sous Linux le pas d'échantillonnage tombe du bon côté ; sous Windows, non.

Corrige par construction, pas en gonflant un délai : la fenêtre de contrat du montage de test doit
être nettement plus courte que l'attente (par exemple un quart), et le test doit vérifier que la
transition se produit **après** la fenêtre et **dans** la marge. Une assertion qui échouerait si la
marge disparaissait à nouveau.

### B. `tests/test_share.py:408` — l'assertion attrape le faux jeu, pas le lanceur
```
assert not list(tmp_path.rglob("*.bat"))
E  AssertionError: assert not [.../test_ac36_generation_writes_no0/pz/StartServer64.bat]
tests\test_share.py:408
```
Le test veut prouver que la route du lanceur n'écrit rien sur disque. Il cherche `*.bat` dans tout
`tmp_path`, qui contient aussi la **fausse installation PZ** du montage — laquelle porte
`pz/StartServer64.bat` sous Windows et `StartServer64.sh` sous Linux. L'intention est bonne, la
portée est fausse.

Resserre l'assertion sur ce que la route pourrait écrire : le nom exact du lanceur, et le dossier de
données de l'application (`XDG_DATA_HOME` / `LOCALAPPDATA` du test). L'assertion doit continuer
d'échouer si la route écrit réellement le `.bat` quelque part dans ce dossier — vérifie-le par un
test qui force cette écriture et doit voir l'assertion tomber.
