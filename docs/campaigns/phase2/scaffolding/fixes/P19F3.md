# P19F3 — Le `.bat` invité se vérifie par un code lu à l'oral, et se déclare réseau de confiance

commit: fix(phase2): P19F3 — Code de vérification du lanceur invité et portée de l'exécution

## Contexte

Constat A3 de la revue de branche : l'invitation voyage en `http://` (imposé par AC37) et le `.bat`
servi exécute PowerShell avec `-ExecutionPolicy Bypass`. Un intermédiaire sur le chemin réseau peut
remplacer la réponse : ce n'est pas une fuite d'information, c'est une **exécution de code** sous le
compte de l'invité. Les empreintes SHA-256 déjà présentes dans le fichier
(`service/guest_launcher.py:179`) protègent les fichiers embarqués entre eux, pas le `.bat` lui-même.

L'opérateur a tranché : **option 1 + option 3**.

## Correction attendue

### 1. Un code de vérification, lu à l'oral par l'hôte
- Le service calcule une empreinte courte et stable du `.bat` qu'il sert (par exemple les 8 premiers
  caractères base32 du SHA-256 du contenu servi, sans les espaces ni la casse).
- L'UI du lobby affiche ce code à côté de l'invitation, en clair, avec une phrase du type « l'invité
  doit voir ce code dans son lanceur ».
- Le `.bat` recalcule à l'exécution l'empreinte de **son propre contenu** (il connaît déjà son chemin
  via `$env:PZDUEL_SELF`) et **refuse de continuer** si elle ne correspond pas au code saisi. La
  saisie se fait par un `set /p` explicite, sans valeur par défaut.
- Conséquence à vérifier et à documenter : un `.bat` remplacé par un attaquant produit un autre code ;
  l'invité qui compare avec ce que l'hôte lui lit **refuse** de l'exécuter.
- Le code doit être **stable** : deux téléchargements du même lobby donnent le même code tant que le
  `.bat` n'a pas changé, et il change dès qu'un octet change.

### 2. Portée de l'exécution et message honnête
- Vérifie d'abord ce que fait réellement `-ExecutionPolicy Bypass` dans ce contexte : s'il ne porte
  déjà que sur le processus, dis-le explicitement dans le code et ne prétends pas l'avoir « resserré ».
  Si un réglage persistant existe quelque part, il doit disparaître.
- Le lanceur et la documentation disent que l'invitation est prévue pour un **réseau de confiance**,
  et que le code est la seule protection contre une substitution. Ajoute la limite dans
  `docs/campaigns/phase2/limites-connues.md` et `.fr.md`, en anglais pour le premier.

## Tests exigés

- Un test qui vérifie la stabilité du code sur deux générations identiques, et son changement sur une
  entrée différente.
- Un test qui vérifie que le code affiché côté UI est calculé sur le **même** contenu que celui servi
  (pas une seconde génération).
- Les tests existants de `tests/test_guest_launcher.py` et `tests/test_share.py` restent verts, sans
  être affaiblis.
