## Constats à corriger

### B1 [major] service/preflight.py:78 — Resolve the installation directory before launching servers

**Preuve de la revue** : Static worktree review only; diff membership could not be verified because git was prohibited. A relative --pz-dir such as game passes detection and remains relative. ServerProcess.start then uses cwd='game' with executable 'game/start-server.sh', causing lookup under game/game and failing an otherwise valid installation. Return an absolute installation path.

**Correction attendue** : Le préflight doit résoudre et valider le dossier d'installation avant tout lancement, y compris --pz-dir et PZ_INSTALL_DIR ; un chemin invalide échoue au préflight, pas au démarrage.

### B2 [minor] service/protocol.py:53 — Reject overflowing numbers in preserved event fields

**Preuve de la revue** : parse_constant does not intercept 1e999, which json.loads converts to infinity. An otherwise valid event containing data.extra=1e999 passes validation because unknown fields are preserved. Journal.write subsequently calls dump_line with allow_nan=False and raises ValueError, terminating the match instead of recording a bad-line anomaly. Reject nonfinite decoded numbers throughout the event.

**Correction attendue** : Le protocole doit refuser les nombres non finis ou hors bornes dans les champs préservés des événements, avec le code d'erreur prévu, sans casser les lignes suivantes.

### B4 [minor] service/engine.py:713 — Validate the effective DayLength before preparing worlds

**Preuve de la revue** : _begin accepts an arbitrary integer day_length override, but this lookup supports only the keys in runtime.day_length_minutes, currently 1 through 7. An override of 8 can pass the contract when the sandbox retains that value, then raise KeyError once both running heartbeats arrive. Validate the effective configuration before restoring worlds and launching servers.

**Correction attendue** : DayLength effectif validé avant la préparation des mondes : une valeur inconnue refuse le lancement sans toucher aux sauvegardes.

### A6 [minor] service/engine.py:1271 — Unvalidated start payload: an unknown day_length kills a running match, and bad types escape the refusal path

**Preuve de la revue** : _begin takes int(payload.get('day_length')) without checking it against runtime.day_length_minutes, while load_table does check the preset value (rules.py:303). With day_length=8, the sandbox write and contract both pass. The first time both sides have a running beat, _drift_end raises KeyError at engine.py:713, and _run_real reports it as 'lancement impossible' mid-match with no match_end. Separately, int('abc') at lines 1264/1271 raises ValueError, which action() does not catch (it catches only ActionRefused), and a non-object JSON body raises AttributeError at api.py:84. Both drop the HTTP connection with no JSON response. The UI only offers 1-4, so this needs a direct API call, which A1 makes easier.

**Correction attendue** : Le payload de start est validé avant tout effet : day_length inconnu, types incorrects et valeurs hors bornes renvoient un refus explicite et n'interrompent pas un match en cours.

### A5 [minor] service/snapshots.py:204 — A world left by an interrupted creation pass can become the permanent origin

**Preuve de la revue** : _creation_pass (snapshots.py:219-225) raises on failure or cancel without removing what the servers created. On the next launch, prepare_worlds sees no snapshot and worlds on both sides, so it calls store.capture (line 204-205). capture only requires that the world folder and the db exist (line 109). A pass cancelled or crashed after both exist is therefore frozen as the origin, and every later match restores it with no warning. The message at line 208 covers only the one-sided case. How incomplete such a world is depends on when PZ writes its files; confirm by cancelling during the first boot. Fix: write a completion marker after a successful pass, or clean up created worlds on failure.

**Correction attendue** : Une passe de création interrompue ne doit pas devenir l'origine permanente : ne capture un snapshot qu'après une passe complète, sinon invalide le monde partiel et le signale.

### A7 [minor] service/engine.py:740 — A decided match result is lost if the end-of-match verdict cannot be computed

**Preuve de la revue** : _conclude re-reads the journal and calls verdict() before writing match_end or setting self.result (engine.py:740-760). JournalError or VerdictError propagates to _run_real, so the match ends as 'lancement impossible', with no match_end and no result, even though MatchCore has already decided the winner. Spec line 497 says attribution must not alter the result, yet a failure of that measurement discards it. One trigger is in journal.py:97-99: a short write raises OSError after leaving a fragment with no newline. The next state line, which _record_state still attempts, then joins it, creating a mid-file unreadable line that read_journal rejects and that also breaks service.replay. Fix: catch the verdict failure, write match_end with an unknown attribution, and terminate or truncate torn journal lines.

**Correction attendue** : Un résultat décidé doit être journalisé même si le calcul du verdict échoue : le résultat et le score sont écrits, l'échec du verdict est journalisé à part.

### A9 [minor] service/engine.py:710 — In-match restart will probably end in invalidation, so the recovery path may rarely save a match

**Preuve de la revue** : After a restart, _first_age is kept and _drift_end resumes once the side is available (engine.py:585, 710-720). The restarted side has lost its downtime (about 20 s to boot per the README) plus, assuming world age reloads from the last save, up to SaveWorldEveryMinutes=5 of progress (runtime.json:60). That is measured against max_drift_s=60 (runtime.json:21), so a crash more than about 40 s after a save would exceed the limit and return 'invalidated'. Spec line 403 accepts 'La dérive tranche ensuite', so this is not a spec violation, but AC38 only tests the double path, where this does not show. Confirm by killing a real server mid-match and comparing age across boots. If it holds, either rebase _first_age on restart or state plainly that restart only preserves the record.

**Correction attendue** : Le redémarrage en match ne doit pas conduire systématiquement à l'invalidation : le temps passé en restarting ne doit pas compter comme dérive, et la reprise repart d'une référence d'horloge cohérente. Documente le comportement par un test.
