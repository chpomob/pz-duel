## Constats à corriger

### A3 [minor] service/engine.py:633 — Unguarded file I/O in the running pump discards a match with no match_end or result

**Preuve de la revue** : Journal writes in the match are protected by _write_safely so that a disk failure cannot lose the result, but the transport calls in the same pump are not. _on_server_exit calls prepare_restart (engine.py:633), which truncates in and rewrites session; poll_ack calls _truncate_in outside its try (transport.py); OutReader._read_from_offset catches only FileNotFoundError. Any other OSError propagates through pump and _drive_match to the generic handler in _run_real, which reports 'lancement impossible' for a match already running. _finish_match then calls _fail, because match.result is None: no match_end is written and the scores held by MatchCore are lost. The failure is also left unhandled exactly when a server has just crashed, the moment _on_server_exit runs. _unavailable has already been updated at that point. Fix: catch OSError in these calls during running and submit_end an invalidated result naming the cause, so the journal always closes.

**Correction attendue** : Protège les appels de transport de la pompe comme les écritures de journal : une `OSError` pendant un match ne doit pas jeter le match sans `match_end`. Sur échec, termine par un résultat invalidé nommant la cause, et le journal se ferme toujours. Test : injecte une `OSError` dans `prepare_restart`, `poll_ack` et la lecture de sortie pendant un match, vérifie qu'un `match_end` invalidé est écrit avec la cause.

### A4 [minor] service/engine.py:1278 — Match cadence and absence timers run on the wall clock, so a clock step can end or freeze a match

**Preuve de la revue** : Engine defaults to time.time (engine.py:1278), and _drive_match feeds it to pump (engine.py:1599). That one value drives MatchCore.advance, _watch_beats and _absence_end. A forward step of at least disconnect_grace_s (120 s in all presets), from NTP correction or suspend/resume, makes both sides look absent and invalidates the match, and advance also catches up every skipped tick. A backward step stops last_tick from rising, so the timer freezes until the clock catches up. Wall time is needed to compare with the mod's t_ms, but not to pace ticks. Assumption: the host clock can step during a 25-minute match, which is plausible on a desktop but untested. Fix: anchor t0 on the wall clock once and derive now_ms from time.monotonic, keeping replay inputs unchanged.

**Correction attendue** : Le rythme des ticks et les minuteries d'absence ne doivent plus dépendre de l'heure murale : ancre `t0` une fois sur l'heure murale et dérive `now_ms` de `time.monotonic`. L'heure murale reste utilisée pour comparer au `t_ms` du mod, pas pour cadencher. Test avec une horloge injectée qui avance de 200 s d'un coup : le match ne doit ni s'invalider ni se figer.

### B1 [minor] service/api.py:196 — A partial request body holds a handler indefinitely

**Preuve de la revue** : _body calls rfile.read(length) without a socket timeout or read deadline. A client can declare an allowed Content-Length, send fewer bytes, and keep the connection open indefinitely. make_server uses ThreadingHTTPServer, so repeated connections retain unbounded threads and sockets. do_POST also performs this read before checking Host or Origin. Bound request reads with a deadline and return an explicit timeout response.

**Correction attendue** : Borne la lecture du corps de requête : délai de lecture explicite, refus 408 en JSON si le corps n'arrive pas, et contrôle `Host`/`Origin` AVANT de lire le corps. Test : client qui déclare une longueur autorisée, envoie moins d'octets et garde la connexion ouverte → réponse JSON dans le délai, thread libéré.

### B2 [minor] service/transport.py:83 — An unterminated output record is repeatedly read without bounds

**Preuve de la revue** : _read_from_offset calls handle.read() without a size limit, while poll advances offset only past complete newline-terminated records. A growing unterminated tail is therefore allocated and scanned again on every poll. A sufficiently large malformed tail can exhaust memory or stall the match pump. Bound both bytes read per poll and record length, with explicit handling for oversized records.

**Correction attendue** : Borne la lecture des enregistrements de sortie : nombre d'octets par poll et longueur maximale d'un enregistrement, avec traitement explicite d'un enregistrement surdimensionné (signalé, jamais accumulé sans fin). Test : queue sans fin de ligne qui grossit à chaque poll → mémoire stable et erreur explicite.
