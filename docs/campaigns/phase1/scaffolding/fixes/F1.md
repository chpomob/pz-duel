## Constats à corriger

### A1 [major] service/api.py:72 — The local API now drives real processes but has no Origin, Host or Content-Type check

**Preuve de la revue** : do_POST (api.py:72-86) parses any body as JSON whatever its Content-Type and passes it to engine.action; grep finds no Origin or Host handling in api.py. Binding to 127.0.0.1 does not stop the user's browser from reaching it. A web page can send a text/plain 'simple' POST to http://127.0.0.1:8765/api/action, which in --mode real can trigger start (restores ~/Zomboid worlds and launches two servers), cancel or open_game (launches Steam, engine.py:1235). With DNS rebinding the page can also read /api/state, which holds config.password and invite (spec line 461 keeps the player password there). The handler code is unambiguous; the reach depends on the browser, since Private Network Access may block some of these requests. Fix: reject any Host other than 127.0.0.1:<port> or localhost:<port>, reject a foreign Origin, and require application/json.

**Correction attendue** : Toute requête vers /api/action et /api/state doit être refusée si l'en-tête Origin est présent et n'est pas l'origine locale attendue, si l'en-tête Host ne correspond pas à l'adresse de liaison, ou si /api/action reçoit un corps dont le Content-Type n'est pas application/json. Ajoute les tests qui échouent sans ce contrôle (Origin étranger, Host étranger, Content-Type text/plain) et un test de non-régression du chemin légitime.

### A2 [major] docs/campaigns/phase1/scaffolding/run_campaign.py:206 — The campaign gate no longer detects a step without a commit: it amends whatever HEAD is

**Preuve de la revue** : Before this change, a wrong subject failed the gate ('SUJET INATTENDU'), and that was the only check that the step had produced a commit. Now run_campaign.py:204-210 runs 'git commit --amend -m expected' on any mismatch. If a loop exits 0 without committing, HEAD is the previous step's commit: it gets renamed to the current step's subject, pytest passes on the unchanged tree, and gate() returns True. The step is reported done with no work, and history now misattributes the previous step. The amend also replaces the whole message, dropping the body and any trailers. Fix: record the HEAD SHA before the loop, fail if it has not moved, and only then amend.

**Correction attendue** : Le gate ne doit plus amender HEAD à l'aveugle. Capture le SHA avant la boucle : si HEAD n'a pas changé, l'étape est un échec (aucun commit produit), jamais un amend du commit précédent. Si HEAD a changé mais que le sujet diffère, alors seulement, amende ce nouveau commit.

### A10 [minor] docs/campaigns/phase1/scaffolding/run_campaign.py:164 — require_clean silently discards .gitignore edits, including the ones in this change

**Preuve de la revue** : When .gitignore is the only dirty path, run_campaign.py:160-165 runs 'git checkout -- .gitignore'. It cannot tell a loop artefact from intended work. This diff's own uncommitted .gitignore additions (.adversarial-loop/, matches/, docs/runs/) would be reverted the same way if they were the only remaining change, leaving matches/ unignored. Fix: commit these entries, and compare against the expected loop artefact before restoring.

**Correction attendue** : require_clean ne doit plus restaurer .gitignore en silence. Compare son contenu à celui d'avant l'étape : identique → restaure ; différent → arrête la campagne en nommant le fichier.
