## Constats à corriger

### A3 [major] service/engine.py:1241 — The only host join path is a Steam client, but the servers run with zomboid.steam=0

**Preuve de la revue** : launch_command uses start-server.sh, and the installed script hardcodes -Dzomboid.steam=0 (~/.local/share/Steam/steamapps/common/ProjectZomboid/projectzomboid/start-server.sh). _open_game_real uses 'steam -applaunch 108600 +connect ... +password' (engine.py:1241-1248), as spec line 457 requires. Assumption: a Steam-mode client may be unable to join a non-Steam server. If so, neither player reaches the lobby, so no probe, hook window or match can run in real mode, and no fallback exists. The README lists this connection as unproven. Confirm with one real client connection before building further on this path; I did not test it, and no authoritative source is cited.

**Correction attendue** : open_game doit fonctionner avec des serveurs lancés en zomboid.steam=0 : lance le client avec +connect/+password par le chemin direct, et ne dépend d'une URL Steam que si elle est réellement disponible.

### A8 [minor] service/engine.py:459 — One shared password opens both servers, and sides are not bound to a player

**Preuve de la revue** : _prepare_launch writes the same config password to duelA and duelB (engine.py:454-462), and the invite gives that password to the guest. _take_beat accepts any username as that side's player (engine.py:836). A guest who tries port 17261 can join A, take its single slot (MaxPlayers=1) and lock the host out, or play in the opponent's world; the engine would count that as the host being present. The default password is also the 5-character code from random.choice (engine.py:171, 1275), not the secrets module. Impact is limited to a friendly duel, but this is the only access control on a game port exposed to the network. Fix: use a distinct password per side, and generate it with secrets.

**Correction attendue** : Chaque camp doit avoir son propre mot de passe, et le camp d'un joueur doit être déterminé par son identité de connexion, pas par un mot de passe partagé.

### A11 [nit] service/snapshots.py:53 — snapshots.py depends on private members of other modules

**Preuve de la revue** : _is_running reads server._process and calls server._group_alive() without _stop_lock (snapshots.py:53), and the module imports the private preflight._check_ports (line 20). The docstring admits ServerProcess lacks a public API for this. A public ServerProcess.running property and a public port check would remove the coupling.

**Correction attendue** : snapshots ne doit plus dépendre de membres privés d'autres modules : expose une API explicite ou déplace la logique.

### A12 [nit] README.md:15 — The README still says the service writes .duel-service.json

**Preuve de la revue** : README.md:15 says the service writes .duel-service.json for tools to find the interface. This diff removes that code from service/main.py, as plan step R2/R7 intended ('.duel-service.json retiré'). Any tool following the README will find no file.

**Correction attendue** : README corrigé : le service n'écrit plus .duel-service.json, ou l'écrit à l'endroit documenté ; aligne le texte sur le comportement réel.
