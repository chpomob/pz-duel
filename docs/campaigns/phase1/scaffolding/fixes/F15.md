# F15 — La table annoncée est la table jouée

commit: fix(phase1): F15 — La table annoncée est la table jouée

## Contexte

Vérification de F14 : A3 RESOLVED, A1 et A2 PARTIAL. A1 est un écart de formulation, pas un
défaut — le moteur juge après l'attente du tampon, ce qui est **plus correct** que de juger
immédiatement (une mort plus ancienne peut arriver dans le tampon, cf. A3). Ne le change pas :
documente-le dans `docs/campaigns/phase1/limites-connues.md` (fenêtre d'attente bornée pendant
laquelle le match tourne sans résultat).

A2 reste un vrai défaut de confiance : ce qui est annoncé n'est pas toujours ce qui est joué.

## Constat à corriger

### A2 [major] — `rules_hash` ne décrit pas la table jouée
`service/engine.py:1279` retire des règles de `_played_table` après un échec mémorisé, alors que
`rules_hash` reste celui de `table` (`service/engine.py:398`), et que `_rules_refusal` ne vérifie
que le preset original (`service/engine.py:1308`). `tests/test_match.py:2232` prévoit ce retrait
au match suivant : la table jouée peut donc encore différer de celle annoncée dans `rules_hash`.

**Correction attendue** : une seule source de vérité. La table effective (celle réellement
appliquée, atomes retirés compris) est calculée avant le scellement, `rules_hash` en dérive, et
l'UI affiche cette même table. Aucun chemin ne doit pouvoir jouer une règle absente du hash ni
annoncer une règle absente du jeu. Si un atome est retiré, le hash et l'affichage changent
ensemble, et le motif du retrait est journalisé.

Tests : atome retiré après un échec mémorisé → `rules_hash` change, l'UI annonce la table réduite,
le journal nomme le retrait ; deux matchs successifs dans le même état produisent le même hash ;
aucune règle jouée n'est absente du hash (test de cohérence croisée table ↔ hash ↔ effets appliqués).
