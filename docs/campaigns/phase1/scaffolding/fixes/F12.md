# F12 — Les tests n'attendent pas la pompe : supprimer la famille d'instabilités

commit: fix(phase1): F12 — Attente déterministe de la pompe dans les tests de match

## Contexte

Le flake signalé deux fois par les gates est identifié. Chasse de 12 passes : rouge au run 4,
sur `tests/test_match.py::test_t0_is_read_on_the_wall_when_the_match_starts` :

    assert duel.state()["score"] == {"A": 1, "B": 0}
    E  AssertionError: assert {'A': 0, 'B': 0} == {'A': 1, 'B': 0}

Le test écrit un kill puis lit l'état immédiatement. L'événement est traité par la pompe, dans un
autre thread : selon l'ordonnancement, la lecture arrive avant l'application. Ce n'est pas un
défaut du moteur, c'est un **test qui suppose un ordre que rien ne garantit**.

## Correction attendue

Ferme la classe, pas ce test :

1. Ajoute au banc d'essai (`tests/conftest.py` ou l'équivalent) une attente déterministe bornée :
   `duel.wait_for(predicate, timeout_s=...)` qui interroge l'état du moteur jusqu'à ce que le
   prédicat tienne, et échoue avec un message explicite (état observé, événement attendu) au-delà
   du délai. Aucun `sleep` fixe : l'attente doit se terminer dès que la condition tient.
2. Recense **toutes** les assertions qui lisent un état produit par la pompe juste après une
   écriture (`duel.kills`, `duel.craft`, `duel.at_match`, événements de transport) et fais-les
   passer par cette attente. Un test qui affirme un effet asynchrone sans point de synchronisation
   est le défaut ; il ne doit plus en rester.
3. Vérifie qu'aucun test ne dépend d'un ordre non garanti entre écriture et traitement.

## Preuve exigée

- Le test identifié passe, et passe pour la bonne raison (l'attente voit le score appliqué).
- **Cinq passes consécutives de la suite complète**, sans échec, avec le compte de tests à chaque
  passe, dans ta réponse finale. C'est cette mesure qui prouve la fermeture, pas une passe unique.
- `.venv/bin/python -m pytest -q` reste sous 90 s par passe.

## Règles

- Ne touche pas au moteur pour « ralentir » ou sérialiser la pompe : le défaut est dans les tests.
- Un seul commit, sujet : `fix(phase1): F12 — Attente déterministe de la pompe dans les tests de match`.
- Réponse finale en français : cause, mécanisme d'attente, nombre de tests convertis, cinq comptes de passes.
